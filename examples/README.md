# Examples

Generated reports from the same offline input, so you can see what each tool produces without an Azure subscription.

## Input

- `data/nsg-app/` and `data/nsg-data/`: three hours (2026-10-18 10:00-13:00 UTC) of `PT1H.json` flow logs for two NSGs. These are synthetic files in the same format Azure writes. Cross-account flows appear at both NSGs, as they do in Azure.
- `topology.json`: maps address prefixes to two storage accounts (`stflowlogsapp01`, `stflowlogsdata02`) and one VNet without flow logs (`vnet-hub`). Public addresses fall into `Internet`. It also names one example subscription and tenant (`Example Production (sample)`, with placeholder GUIDs), which the reports show in their Tenant and Subscriptions rows. Live reports read these values from Azure instead.

The reports use `--since 2026-10-18T10:00:00Z --until 2026-10-18T13:00:00Z`.

## Scenarios

| Scenario | What it shows |
|----------|---------------|
| `all` | Every observation: traffic between the two storage accounts, to the internet and to the hub VNet |
| `deny-only` | Only denied traffic (`--action deny`): the 8080 rule at the data NSG and the SSH deny from the hub |
| `sql-1433` | SQL traffic only (`--port 1433 --protocol tcp`) |
| `app-subnet` | Everything touching the app subnet (`--ip 10.10.1.`) |

## .NET tool (`examples/dotnet/`)

The same reports are produced by the Rust binary (`rust/target/release/azure-flowlog-parser`), which is not committed here because its report payload is identical to the .NET one.

```bash
azure-flowlog-parser report --input examples/data --topology examples/topology.json \
  --since 2026-10-18T10:00:00Z --until 2026-10-18T13:00:00Z --report html -o flowlog-report-all.html
```

Add `--report pdf` for the PDF version, or the filter flags shown in the table above.

## PowerShell modules (`examples/powershell/`)

```powershell
Import-Module ./powershell/AzureFlowLogParser/AzureFlowLogParser.psd1
Import-Module ./powershell/AzureFlowLogReport/AzureFlowLogReport.psd1

$model = Get-FlowLogTraffic -InputPath ./examples/data -TopologyPath ./examples/topology.json `
    -Since '2026-10-18T10:00:00Z' -Until '2026-10-18T13:00:00Z'
$model | Export-FlowLogReport -Format Html -Path ./flowlog-report-all.html
$model | Export-FlowLogReport -Format Pdf -Path ./flowlog-report-all.pdf
```

For the filtered scenarios, add `-Action Deny`, `-Port 1433 -Protocol TCP` or `-IpFilter 10.10.1.` to `Get-FlowLogTraffic`.

## Checking the tools agree

The .NET, PowerShell and Rust tools read the same input and produce identical report payloads (the embedded JSON, ignoring `generatedUtc`) for all four scenarios and for the sample flow log. The `all` scenario gives:

| Measure | .NET | PowerShell |
|---------|------|------------|
| Flow observations | 301 | 301 |
| Allowed / denied | 240 / 61 | 240 / 61 |
| Duplicates skipped | 99 | 99 |
| Aggregated rows | 242 | 242 |
| Bytes | 15,889,587 | 15,889,587 |
| Subscriptions | 1 (Example Production (sample)) | 1 (Example Production (sample)) |

The `app-subnet` scenario also matches (257 observations, 206 rows). Both tools' HTML files use the same template. The PDFs are laid out to the same sections and column widths, but are not byte-identical.

The examples are committed as generated output. They are not regenerated by the test suites.
